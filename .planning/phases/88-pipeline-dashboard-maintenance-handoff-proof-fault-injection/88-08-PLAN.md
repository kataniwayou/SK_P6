<objective>
Measure the minimum detectable fault duration, and collapse everything the phase has proven into a
single fourteen-row panel-keyed matrix.

The roadmap treats the minimum duration as one number. It is two, because counters and gauges fail
differently: a counter is cumulative, so a fault entirely between two exports still increments it
and only its TIMING is smeared across the 240-second rate window; a gauge is sampled, so a
condition that begins and ends between two 60-second exports is never recorded at all. Reporting
one number would mislead maintenance in exactly the direction this phase exists to prevent.

The roll-up is keyed by PANEL, not by scenario, because the unit of proof here is the panel. One
scenario can prove several panels and one panel can appear in several scenarios' cross-talk lists.

Purpose: satisfy DISC-07 and produce the artifact HAND-01, HAND-02, HAND-03 and HAND-04 all read
from.
Output: `-Mode DurationLadder`, `analyzer-reports/phase-88-LADDER-01.json`,
`scripts/phase-88-rollup.ps1`, `analyzer-reports/phase-88-discrimination.json`.
</objective>

<!-- The ladder design and the roll-up schema. -->

The signal chain that sets the floor (measured in Phase 87 §11, not assumed): fault occurs -> the
SDK's PeriodicExportingMetricReader exports every 60 s -> the collector forwards with explicit
millisecond timestamps -> Prometheus honours the explicit timestamp and discards re-scrapes bearing
one it already stored, so the STORED resolution is 60 s, not the 15 s scrape interval -> Grafana
`rate()` over 240 s -> the panel.

Counter ladder (panels 3 and 4, lever `scale` on processor-sample):
    rung 1  30 s      rung 2  60 s      rung 3  120 s      rung 4  240 s      rung 5  480 s
  Between rungs: restore, then wait for the rate window to clear FULLY (at least 240 s) plus a
  settle, so each rung is an independent measurement rather than a tail of the previous one.
  Theory to record alongside the measurement: a fault of duration D that drops a rate to zero
  produces a trough of about `baseline x (1 - D/240)`, so D = 60 s gives about a 25 % dip, 120 s
  about 50 %, and D >= 240 s reads 0. The smallest rung whose dip clears the Regime-A band for two
  consecutive samples is the measured answer. Research PREDICTS 120 s; the ladder replaces the
  prediction with a number.

Gauge ladder (panel 14, lever `http`):
    rung 1  30 s      rung 2  60 s      rung 3  120 s      (and 180 s if all three fail)
  Same independence discipline. Research PREDICTS >= 120 s and notes that anything shorter is a
  coin flip, because a request that begins and ends between two exports is invisible.

Regime B is a third answer and must be stated explicitly rather than folded into the other two: for
a zero-floor guarded counter a SINGLE event is detectable at ANY duration, because the counter goes
from 0 to 1 and stays there for the whole `$__range` window. That is the strongest detection
property on the dashboard and maintenance should know it.

Ladder artifact fields:
  ScenarioId, Verdict, Rungs[] each { Regime, PanelIds[], FaultSeconds, Lever, BaselineBand,
      AfterValues[], AfterStates[], Moved, ConsecutiveSamplesOutside, DipFraction,
      TheoreticalDipFraction, RungStartUtc, RungEndUtc, ReplicasRestored },
  MinDetectableCounterSeconds, MinDetectableGaugeSeconds, RegimeBDetectionNote,
  PredictedCounterSeconds, PredictedGaugeSeconds, PredictionAgreesWithMeasurement,
  SubWindowSeconds, ViewportWidth, ViewportHeight, RateIntervalSeconds, OldestSampleUtc,
  SeamVarsClean, ReplicasRestored, ImagesUnchanged, HumanSummary

Roll-up schema — `analyzer-reports/phase-88-discrimination.json`, a JSON ARRAY of exactly fourteen
camelCase rows, one per panel (the `analyzer-reports/phase-81-summary.json` shape, re-keyed):
  { panelId, panelTitle, regime,
    baselineBandSeries[] each { seriesName, low, high, floorApplied },
    baselineBand: {low, high, floorApplied, seriesCount, collapsedFrom[]},
    observedStates[], provenBy (scenario id or null), status ('Proven'|'AcceptedUnproven'),
    reason, misleadingByDefault: {flag, note}, crossTalkAppearances[], sourceArtifact }
A missing proof is a ROW with status `AcceptedUnproven` and a reason, never an absence.

Multi-series band collapse — the one place BASE-01's shape and the roll-up's shape disagree,
resolved here so the executor does not have to invent a rule mid-run. BASE-01 emits one
`BaselineBands[]` entry PER LEGEND SERIES, and nine of the fourteen panels (1, 2, 3, 5, 9, 10, 11,
12, 14) carry two or more, so "the panel's band" is not a single value in the source artifact.
The rule: `baselineBandSeries[]` reproduces every per-series entry VERBATIM so nothing is lost,
and `baselineBand` is their WIDEST ENVELOPE — `low` = the minimum `BandLow` across the entries,
`high` = the maximum `BandHigh`, `floorApplied` = true if ANY contributing series had a floor
applied — carrying `seriesCount` (how many entries were collapsed) and `collapsedFrom[]` (their
series names) so the collapse is auditable from the artifact alone.
The envelope is a HUMAN SUMMARY for reading the matrix, nothing more. No scenario scores against
it: every movement decision was already made PER SERIES by the scenario harness against the
per-series band, and the roll-up's standing rule — never recompute a verdict, a band or a
movement — is unaffected. Choosing a "first" or "primary" series is explicitly REJECTED: it would
silently discard a series whose band differs, which is exactly the kind of hidden evidence loss
this matrix exists to prevent. Single-series panels collapse trivially to themselves with
`seriesCount` 1. Regime-B panels stay at 0/0 because every contributing series is 0/0.
