<objective>
Flip the framework's payload spine `DataResult.Data` from `string` to `byte[]` — the single ground-truth type — and migrate every typed production consumer in the same wave so the `src/` solution reaches a green build. Base64 leaves the hot path; JSON/UTF-8 becomes an optional schema lens over opaque bytes.

Purpose: byte[] is the prerequisite channel the Phase-85 KafkaImporter writes binary files into. This phase is framework-only (no Kafka).
Output: `DataResult.Data` is `byte[]`; D-02 edge helpers (encode-on-write `NewResult(string)`, `NewResult(byte[])` overload, decode-on-read `DataAsString`); the processor seam, pipeline read, schema validator, and both concrete processors carry `byte[]`.

SCOPE FENCE (locked by orchestrator, OQ-1): `NextStepHandoff.Data` STAYS `string`. Do NOT touch `Orchestrator/Dispatch/OrchestratorPrePipeline.cs`, `RelocateTail.cs`, `Keeper/Recovery/OrchestratorInjectConsumer.cs`, `NextStepHandoff.cs`, or `OrchestratorInject.cs`. The orchestrator relocate round-trips UTF-8 JSON byte-for-byte losslessly for the sweep; widening it for genuine binary is deferred to Phase 85. Do NOT let DATA-05's wording pull the orchestrator relocate into scope.

NO BRIDGE (D-03): do not add any temporary `string`↔`byte` bridge, no parallel `byte[]? Binary` field, no discriminator. One field, always bytes.
</objective>
