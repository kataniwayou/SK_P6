<objective>
Strip the redundant Tier-1 execution-id placeholders from the processor's per-hop framework record (D1 / LOG-01). The `hop executed` template currently restates `{StepId} {ExecutionId} {CorrelationId} {EntryId}` — all five of which the bus-wide `InboundExecutionScopeConsumeFilter` already emits as `attributes.*` scope values. Remove them from the string; keep the Tier-2 `{MessageId}` (the one delivery id the scope does not carry) and the Tier-3 `{Outcome}` (D6 / LOG-06 — the emitting component knows the outcome at emit time).

Purpose: one uniform logging pattern where no id is ever duplicated in a string the scope already carries.
Output: `ProcessorPipeline.LogHopExecuted` emits `"hop executed {MessageId} {Outcome}"`; the existing hermetic per-hop fact suite updated to the new shape.

PHASE-78 HANDOFF (documented, do NOT fix here): the Mode-2 entry step has `ExecutionId == Guid.Empty`. Today its all-zeros value surfaces ONLY because `{ExecutionId}` is an explicit placeholder arg. Once stripped, `BuildState` skips the empty GUID, so the entry marker's `attributes.ExecutionId` becomes ABSENT (not zero). The live analyzer's entry-marker detection (`PassFailEngine.IsEntryMarker`, `== Guid.Empty`) must switch to "attribute absent" — that is Phase 78 (Category=RealStack, not in the hermetic build).
</objective>
