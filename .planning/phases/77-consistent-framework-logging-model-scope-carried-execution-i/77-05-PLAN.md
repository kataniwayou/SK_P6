<objective>
Lay the D2 (LOG-02) foundation the keeper scope-open (Plan 06) builds on — in the shared `Messaging.Contracts` assembly, so it lands in Wave 1 before the keeper consumers change.

Two coordinated pieces:
1. **`ExecutionLogScope.BuildState` positional overload.** The keeper recovery messages carry the five execution ids but are NOT `IExecutionCorrelated`, so the existing `BuildState(IExecutionCorrelated)` cannot build their scope. Add `BuildState(Guid workflowId, Guid stepId, Guid processorId, Guid executionId, Guid entryId)` with the byte-identical skip rules (each `Guid.Empty` skipped; EntryId skipped when `SourceStep.IsSource`), and make the existing overload DELEGATE to it — one skip-rule implementation, honoring the doc's "never inline `== Guid.Empty`" rule.
2. **`IKeeperRecoverable : ICorrelated`.** DISCOVERED NECESSITY: `ExecutionLogScope` deliberately never scopes CorrelationId (it is owned by the bus-wide `InboundCorrelationConsumeFilter`, which sources it from `context.Message as ICorrelated`). Today the keeper records are NOT `ICorrelated`, so on a keeper consume the correlation filter falls back to the envelope id — and the outbound `OutboundCorrelationSendFilter` only stamps the envelope for `ICorrelated` sends, so a keeper send leaves it unstamped → a FRESH Guid fallback. That means once Plan 06 strips `{CorrelationId}` from the keeper reinject logs, CorrelationId would arrive WRONG. Making `IKeeperRecoverable : ICorrelated` fixes both ends (body-sourced on consume, envelope-stamped on send) — exactly mirroring how `IExecutionCorrelated : ICorrelated` already works. CorrelationId is re-declared with `new` so MassTransit's `UsePartitioner` 4-tuple (`GetProperties()` surfaces only directly-declared members, D-12) is byte-for-byte preserved.

Purpose: give the keeper consumers a buildable execution scope AND a correct correlation source before they strip their Tier-1 placeholders.
Output: the overload + delegation; the interface change (partition-preserving); a hermetic fact locking down parity, skip rules, the ICorrelated contract, and the partition 4-tuple shape.
</objective>
