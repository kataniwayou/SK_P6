<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pod → kube-apiserver | The orchestrator pod authenticates to the API server with its in-cluster ServiceAccount token to read/write the Lease |
| election callbacks → LeaderState | The only sanctioned mutation path for the shared leadership snapshot |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-01 | Elevation of Privilege | KubernetesClient in-cluster credential | mitigate | `InClusterConfig()` uses ONLY the pod's mounted ServiceAccount token; the SA is granted least-privilege lease-only access by Plan 03 RBAC (no wildcard verbs/resources). This plan hard-codes ns `skp` + lease `orchestrator-leader` — no dynamic namespace/name from untrusted input |
| T-82-02 | Tampering | LeaderState snapshot | mitigate | Single-writer invariant: the volatile snapshot is mutated post-construction ONLY by the election callbacks; writer methods have no other callers (grep-enforced in acceptance) — a rogue second writer cannot flip leadership |
| T-82-03 | Denial of Service | election renew loop | accept | A flapping apiserver could churn acquire/renew; bounded by RetryPeriod 2s / RenewDeadline 10s and confined to one pod's fire gate. Live behavior is Phase-83 scope; no build-time mitigation needed |
| T-82-04 | Information Disclosure | election log lines | accept | Logs carry only role + leader identity (pod name), no secrets/tokens; low-value |
</threat_model>
