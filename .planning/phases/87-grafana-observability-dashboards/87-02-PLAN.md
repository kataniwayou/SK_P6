## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host -> cluster | `kubectl port-forward` is the only ingress; Services stay ClusterIP with no NodePort and no Ingress |
| browser/script -> Grafana HTTP API | Unauthenticated anonymous Viewer plus admin basic auth, both reachable only over loopback |
| Grafana -> Prometheus | Server-side `access: proxy` fetch over in-cluster Service DNS; the browser never contacts :9090 |
| repo ConfigMap -> Grafana provisioning tree | Mounted read-only into a directory Grafana executes configuration from at boot |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-87-01 | Information Disclosure | `kubectl port-forward svc/grafana 3000:3000` | mitigate | Bind `--address 127.0.0.1` explicitly, never 0.0.0.0, exactly as the existing 8 forwards do (extends the documented T-80-17 control at scripts/phase-80-up.ps1) |
| T-87-02 | Elevation of Privilege | default `admin`/`admin` credentials | accept | Confined to loopback by the ClusterIP + loopback-forward posture; identical to the stack's existing unauthenticated Prometheus and Elasticsearch. | T-87-04 | Information Disclosure | Grafana outbound analytics / update checks from a dev cluster | mitigate | `GF_ANALYTICS_REPORTING_ENABLED=false` and `GF_ANALYTICS_CHECK_FOR_UPDATES=false` |
