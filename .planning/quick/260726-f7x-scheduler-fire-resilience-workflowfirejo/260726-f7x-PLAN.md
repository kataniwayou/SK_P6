<objective>
Make the Quartz self-rescheduling fire chain resilient to a single infra send fault. Today
`WorkflowFireJob.Execute` dispatches entry steps in a `foreach` over `wf.EntryStepIds` via
`dispatcher.DispatchAsync(...)`, and `StepDispatcher.DispatchAsync` is a bare `endpoint.Send(...)`
with NO retry. On an infra send fault the exception propagates OUT of `Execute`, skipping BOTH the L1
liveness refresh AND `scheduler.RescheduleAsync(...)` at the bottom. Because the trigger is a
self-rescheduling NON-DURABLE one-shot, the skipped reschedule leaves no next trigger → Quartz
auto-purges the job → the workflow silently stops firing (host does not crash; JobRunShell catches).

Fix: wrap the per-entry-step `DispatchAsync` call in a try/catch INSIDE the existing `foreach`
(the `if (fireEnabled)` branch), mirroring the existing business-skip `continue` pattern. On an infra
send fault: LOG a warning (ids in the already-open scope) and `continue`, so the loop finishes and
Execute falls through to the L1 liveness refresh + `RescheduleAsync`. Cancellation from
`context.CancellationToken` (host shutdown) is NOT swallowed. The swallow lives ONLY in the fire path.

Purpose: keep the schedule chain alive across a transient broker blip on the fire send so the workflow
keeps firing on the next cron tick, instead of going permanently silent on the leader until restart/failover.
Output: one failing-then-passing hermetic test + the WorkflowFireJob fix + aligned doc comments.
</objective>
