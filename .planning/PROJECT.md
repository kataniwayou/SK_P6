# Steps API

## Current Milestone: v10.0.0 Orchestrator High Availability

**Goal:** Run the orchestrator as N≥2 replicas with single-leader mutual exclusion so horizontal scaling never produces duplicate workflow triggers, with fast failover and role-tagged observability.

**Target features:**
- Leader election over a `coordination.k8s.io/v1` Lease via the `KubernetesClient` `LeaderElector` (`RunAndTryToHoldLeadershipForeverAsync`) hosted in a `BackgroundService`; single-writer volatile `LeaderState` snapshot (all replicas start as followers).
- Leader-only gate on `WorkflowFireJob`'s entry-step send loop (the sole duplication source — each replica's Quartz fires the same cron and mints a fresh random correlationId); `RelocateTail`/step-advancement stays ungated so in-flight workflows never stall on failover.
- `attributes.role = leader|follower` on every orchestrator log via an OTel `LogRecord` enricher (mirrors `ProcessorIdLogEnricher`).
- RBAC for `leases` in `skp` + orchestrator Deployment scaled to N≥2; new `KubernetesClient` dependency.
- Failover proof: kill the leader mid-run, prove zero duplicate triggers (distinct per-fire correlationIds) + bounded single-leader recovery.

**Requirements:** HA-01..HA-07 (REQUIREMENTS.md). **Phases:** 82 (leader election), 83 (failover proof). Builds on v9.0.0 (k8s deploy, phases 80-81, complete-but-unarchived).

## Milestone History: v7.0.0 — Per-Replica Processor Liveness & Self-Watchdog

**Goal:** Make processor liveness multi-replica-accurate and self-healing — L2 reflects every replica's true state (including a restarting one), orchestration admits a workflow if *any* replica is healthy-and-fresh, and a silently-crashed liveness loop restarts its own pod.

**Target features:**
- **Per-instance L2 keys** — `skp:proc:{processorId}:{instanceId}` (TTL = source of truth) + instance-index SET `skp:proc:{processorId}` (`SMEMBERS` discover, lazy `SREM` prune). The startup loop writes *unhealthy* entries from its first iteration, so L2 reflects a restarting replica (never absent). `configSchema` reuses v6.0.0's Gate A outcome.
- **In-memory L1 liveness record** — both the startup loop and the heartbeat loop update L1 + L2 each iteration.
- **Split interval config** — `startup_interval` + `heartbeat_interval` (heartbeat refreshes timestamp only; health is frozen healthy once the heartbeat loop starts — monotonic within a process, resets across restart).
- **WebAPI ≥1-healthy orchestration-start gate** — iterates the instance index; passes iff **≥1** replica is present **and** `status=healthy` **and** non-stale (`timestamp + interval×2 > now`). Present-but-unhealthy fails that replica. (Removes today's "present ⟺ live" assumption.)

K8s probe *wiring* is future; this milestone builds the probe semantics.
- **Drop schema definitions from L2** — `inputDefinition`/`outputDefinition` are write-only dead weight today (no consumer reads them from L2; the processor validates against its own L1 copy). The L2 per-instance value becomes liveness-only.

**Key context:** Breaking change to the processor liveness contract — the L2 keyspace reshapes (single key → per-instance keys + index), the projection/wire shape changes, and the WebAPI orchestration-start gate logic changes. ## Milestone History: v3.5.0 Processor Console — Self-Registration, Liveness & Execution Round-Trip

- **Assembly-embedded SourceHash** — MSBuild target (`BeforeTargets=CoreCompile`): SHA-256 (lowercase 64-hex, LF-normalized, per-file → folded) over `BaseProcessor.Core` + the concrete's `.cs`, emitted as `[assembly: AssemblyMetadata("SourceHash", …)]`, read at runtime by reflection. Re-runs on source change; excludes `BaseConsole.Core`/`Messaging.Contracts`.
- **WebApi bus responders** (relaxes the v3.4.0 publish-only firewall) — `GetProcessorBySourceHash` → `{ Id, InputSchemaId?, OutputSchemaId?, ConfigSchemaId? }` and `GetSchemaDefinition(schemaId)` → `{ Definition }`; the processor holds the `IRequestClient`s (first request/response on the console side).
- **Shared-contract extracts** to `Messaging.Contracts` — `ProcessorProjection` made public + relocated; the two new request/response contracts added; a new `L2ProjectionKeys.ExecutionData(entryId)` builder (`skp:data:{entryId:D}`).
- **Two-loop startup** — Loop A: bus-query identity by SourceHash, retry-on-failure → launch the liveness heartbeat worker → Loop B: bus-query the input + output definitions for each non-null schema Id, retry-on-failure → write to L2, exit.
- **Liveness heartbeat worker** — every `Interval`s write/refresh `skp:{processorId:D}` = `{ inputDefinition, outputDefinition, liveness{ timestamp, interval, status: "Healthy" } }` with `Ttl` expiry, written **only while Healthy** (identity + required definitions resolved). A starting/restarting replica doesn't write — to the orchestrator it's `absent`. Multi-replica safe & lock-free: the shared key is a blind whole-value `SET` of equivalent content (last-write-wins); execution-data keys are unique per result. The v3.4.0 `ProcessorLivenessValidator` is reused **unchanged** (presence+freshness ⟺ "≥1 replica healthy").
- **Execution round-trip** — consume `EntryStepDispatch` on `queue:{processorId:D}` → resolve input from `L2[data(entryId)]` (existence-checked) + validate vs `inputDefinition` (skip when empty) → `abstract ProcessAsync(inputData, config, ct)` where `config` = the dispatch `Payload` → per result: validate output vs `outputDefinition`, mint `entryId` + write `L2[data(newEntryId)]`, mint per-result `executionId` → send `ExecutionResult` one-by-one to `queue:orchestrator-result` → ack after all sends (empty list + no fault → ack only; Failed/Cancelled always sent).
- **Config** — two independent appsettings knobs: `Interval` (s; heartbeat delay, written as L2 `interval`) and `Ttl` (s; liveness key expiry); execution-data keys get their own configurable TTL.

**Key context / locked decisions:**
- The L2 reader half already shipped in v3.4.0 and expects this external self-registrar: `ProcessorLivenessValidator` (key `skp:{id:D}`, stale at `timestamp + interval×2`, 422 + RFC 7807) and the deliberately-empty `RedisProjectionWriter` (Phase 22 PROC-NOCREATE-01).
- The `Orchestrator` and the `EntryStepDispatch`/`ExecutionResult` wire contracts are reused **unchanged** — the orchestrator already forwards the carried-but-unused `EntryId`/`ExecutionId` end-to-end; this milestone gives them runtime meaning (`EntryId` = output-data L2 key, `ExecutionId` = per-result id).
- SourceHash is lowercase 64-hex to satisfy the existing DB validator (`^[a-f0-9]{64}$`); the Processor DB row is registered manually via CRUD using the hash read off the built binary; the processor retries identity until the row exists (boot-before-register).
- The virtual seam is `abstract Task<IReadOnlyList<ProcessResult>> ProcessAsync(string inputData, string config, CancellationToken ct)`; the framework owns all id-minting, validation, L2 read/write, and result sending so a new processor overrides only `ProcessAsync`.
- Input data is read only from L2 (`Payload` is config, never input data); the result contract stays outcome-only (no step-to-step data on the wire); processing relies on the orchestrator's liveness gate (no special dispatch-bind timing this milestone).

**Out of scope (deferred):** real (non-dummy) transform logic; step-to-step output-data forwarding on the wire; config re-validation in the processor; cleanup-on-read of execution-data keys; orchestrator-side entry-step L2 seeding.

## Constraints

- **Tech stack — runtime:** .NET 8 (LTS). *Reason: user-specified.*
- **Tech stack — database:** PostgreSQL via the official Docker image. *Reason: user-specified.*
- **Tech stack — ORM:** EF Core 8 + Npgsql (`Npgsql.EntityFrameworkCore.PostgreSQL`). *Reason: native Guid↔uuid mapping, audit interceptor, generic repository, idiomatic for the stack.*
- **Tech stack — mapping:** Mapperly. *Reason: source-generated, zero runtime reflection, AOT-safe, modern .NET 8 standard.*
- **Tech stack — validation:** FluentValidation. *Reason: inheritable validators match the base→concrete extension pattern; SemVer regex and per-entity rules compose cleanly.*
- **Tech stack — observability:** OpenTelemetry .NET SDK with OTLP exporter. *Reason: user-specified Collector destination, vendor-neutral.*
- **Tech stack — error format:** RFC 7807 Problem Details. *Reason: built-in to ASP.NET Core, standard, machine-readable.*
- **Architecture:** Single deployable service (modular monolith). *Reason: cross-entity FKs + single-team + milestone speed; bounded-context separation by code organization, not by deployment.*
- **Persistence:** Single Postgres database, single `AppDbContext`, DB-level FK constraints. *Reason: forced by cross-entity FKs.*
- **Identity strategy:** all primary keys are `Guid`. *Reason: user-specified.*
- **Version semantics:** `Version` field is metadata (mutable in place via PUT, no `(Name, Version)` uniqueness). *Reason: user-specified.*
- **CRUD only at base:** no execution, scheduling, or business behaviors at the API surface. *Reason: scope boundary; orchestration is external.*
