<objective>
Reshape the three keeper recovery consumers to the two-consumer model (req 6/7/8) and migrate their facts (D-17 / req 12). INJECT becomes DataResult-driven (write `OutputData(messageId)` completed-only, send by result with the envelope MessageId override, delete the source entry). DELETE becomes a single-key entryId-only delete. REINJECT adds the per-send envelope MessageId override on re-inject.

Purpose: the keeper is the out-of-band L2-op completer; under the new model it operates on `skp:out:{messageId}` (not the retired slot/index) and overrides the outbound envelope `MessageId` so a re-injected/recovered message reuses the carried id (req 6/11).
Output: 3 reshaped consumers + 3 migrated fact files + extended `RecoveryTestKit`. Runs parallel with Plan 03 (zero file overlap — Keeper src/tests vs BaseProcessor.Core src/tests).
</objective>

    protected override async Task HandleAsync(KeeperInject m, CancellationToken ct)
    {
        var dr = m.DataResult;   // D-13: the whole self-contained result (req 7 — never read input to recompute)

        // 1) write L2[messageId]=data — gated on Completed (A2; consistent with Pre/Post inline tail).
        if (dr.Result == StepOutcome.Completed)
            await Guard(() => Db.StringSetAsync(
                L2ProjectionKeys.OutputData(dr.MessageId), dr.Data, JitteredTtl()), ct);

        // 2) send Step* by result, envelope MessageId overridden to the carried messageId (req 6/11).
        IStepResult step = dr.Result switch
        {
            StepOutcome.Completed  => new StepCompleted(dr.WorkflowId, dr.StepId, dr.ProcessorId)
                                          { CorrelationId = dr.CorrelationId, ExecutionId = dr.ExecutionId, EntryId = Guid.Empty },
            StepOutcome.Failed     => new StepFailed(dr.WorkflowId, dr.StepId, dr.ProcessorId)
                                          { CorrelationId = dr.CorrelationId, ExecutionId = dr.ExecutionId, EntryId = Guid.Empty, ErrorMessage = "output failed schema validation" },
            StepOutcome.Cancelled  => new StepCancelled(dr.WorkflowId, dr.StepId, dr.ProcessorId)
                                          { CorrelationId = dr.CorrelationId, ExecutionId = dr.ExecutionId, EntryId = Guid.Empty, CancellationMessage = "" },
            _                      => new StepProcessing(dr.WorkflowId, dr.StepId, dr.ProcessorId)
                                          { CorrelationId = dr.CorrelationId, ExecutionId = dr.ExecutionId },
        };
        var ep = await Guard(() => Send.GetSendEndpoint(new Uri($"queue:{OrchestratorQueues.Result}")), ct);
        await Guard(() => ep.Send((object)step, ctx => ctx.MessageId = dr.MessageId, CancellationToken.None), ct);

        // 3) delete L2[entryId] (the source DeleteEntryId) — AFTER the confirmed send (Pitfall 5 order).
        await Guard(() => Db.KeyDeleteAsync(L2ProjectionKeys.ExecutionData(m.DeleteEntryId)), ct);
    }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internal bus → keeper-recovery queue | Keeper* messages arrive on the partitioned recovery queue; same internal-RabbitMQ trust boundary as the entry queue |
| keeper → Redis L2 | Guid-typed keys (`skp:out:{messageId:D}`, `skp:data:{entryId:D}`) |
| keeper → orchestrator-result queue | INJECT re-emits a Step* with the envelope MessageId overridden to the carried id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-04 | Spoofing | envelope MessageId override on INJECT/REINJECT re-emits a chosen MessageId | accept | Reusing the carried messageId is by-design (req 6/11); no MassTransit inbox/dedup is configured on these endpoints (verified — no UseMessageRetry/UseInMemoryInboxOutbox), so a reused id cannot be exploited to drop messages; at-least-once delivery is the documented posture. |
| T-70-05 | Tampering | INJECT writes attacker-influenced `dr.Data` to L2 | accept | `dr.Data` originated from the processor's own validated output on the same internal bus; no new external input boundary; key is Guid-formatted (no injection). |
| T-70-06 | Denial of Service | DELETE drop-on-absent / send-exhaust throw | mitigate | Bounded RetryLoop via `Guard` then rethrow → broker nack-requeue (existing posture); no unbounded retry; partitioner serializes per-exec so one exec cannot starve others. |
</threat_model>
