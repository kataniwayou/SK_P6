<objective>
Strip the redundant Tier-1 execution-id placeholders from the orchestrator's execution-path framework records (D1 / LOG-01) and add the outbound `{MessageId}` capture on the fan-out send (D3 / LOG-03). The scope filter already emits WorkflowId/StepId/ProcessorId/ExecutionId/EntryId as `attributes.*`; restating them in `terminal reached`, `fan-out`, and the business trip-end lines is pure duplication. Keep the Tier-3 domain extras (`outcome={Outcome}`, `{NextStepId}`) per D6/LOG-06. On fan-out, mint the outbound envelope id and log it (`fan-out {MessageId} {NextStepId}`) — this reverses D-11 Option C's "outbound id not in hand" by capturing it via the send-context callback.

Purpose: uniform orchestrator logging — Tier-1 from scope, `{MessageId}` on send, domain extra otherwise.
Output: `OrchestratorPrePipeline` execution-path templates stripped; fan-out stamps+logs its outbound id; the pipeline fact suite updated.

SCOPE FENCE: change ONLY the six execution-path records enumerated below. Do NOT touch the orchestrator lifecycle/hydration/scheduling/pause-resume logs (`PauseAllConsumer`, `ResumeWorkflowConsumer`, `WorkflowLifecycle`, `WorkflowFireJob`, `HydrationBackgroundService`, etc.) — those are operational diagnostics carrying a single relevant id, not part of the three-tier execution-evidence model, and are out of scope for this phase.
