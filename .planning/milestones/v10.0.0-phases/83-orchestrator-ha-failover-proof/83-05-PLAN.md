<objective>
Fix the Phase-82 mechanism defect the HA-07 live proof caught: the orchestrator cannot run at replicas:3 because its three fan-out consumer endpoints (`orchestrator` for Start/Stop, `orchestrator-pauseresume` for Pause/Resume, `orchestrator-global-pauseresume` for PauseAll/ResumeAll) are declared with a FIXED `EndpointName` while `Program.cs` asks for `.Endpoint(e => { e.InstanceId = …; e.Temporary = true; })`. In MassTransit 8.5.5 a literal `EndpointName` BYPASSES the InstanceId-aware name formatter, so the queues get the fixed base name + `Temporary=true` (exclusive) → at replicas>1 the 2nd/3rd replica hit `RESOURCE_LOCKED`, the bus faults, `/health/ready` returns 503, and the deployment never reaches 3/3.

Make the three fan-out endpoint groups PER-INSTANCE while preserving co-location per pair, add a hermetic regression guard, and leave the shared competing-consumer `orchestrator-result*` endpoints untouched. This unblocks the live HA-07 proof (83-04).
</objective>

<why_this_is_safe>
- All three message families are PUBLISH-by-type — Start/Stop via `IPublishEndpoint` (OrchestrationService.cs:266), PauseAll/ResumeAll via `bus.Publish` (Keeper BitHealthLoop.cs:72,82); Pause/Resume-workflow likewise published. Publish routes by the message-type EXCHANGE binding, NOT the queue name, so renaming the queues per-instance CANNOT break delivery. Verified: NO `.Send`-by-name to any of these three queues anywhere in src (the only `.Send`s target `orchestrator-result-post` / keeper recovery, which are NOT touched).
- Proven precedent: the processor runs N-replica by building an explicit per-instance queue name (ProcessorStartupOrchestrator.cs:267, `ConnectReceiveEndpoint($"{context.Id:D}")`). Per-instance naming is the established multi-replica pattern; the orchestrator's static fixed `EndpointName` was the anti-pattern.
- Co-location matters for the pause/resume pairs: Pause+Resume (and PauseAll+ResumeAll) share ONE endpoint with `ConcurrentMessageLimit=1` to serialize Pause vs Resume against EACH OTHER. Splitting them would break that serialization — so the fix keeps each pair on the SAME per-instance name.
- `Temporary=true` stays: with a unique-per-pod name, an exclusive/auto-delete queue is correct (auto-cleans on pod death; no cross-replica collision).
</why_this_is_safe>
