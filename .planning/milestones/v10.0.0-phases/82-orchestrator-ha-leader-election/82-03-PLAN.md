## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestrator SA → kube-apiserver | The RBAC Role is the sole grant scoping what the orchestrator pod may do against the API |
| Lease object (skp/orchestrator-leader) | A shared coordination object every replica contends for |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-09 | Elevation of Privilege | orchestrator RBAC Role | mitigate | Least privilege: a single namespaced (skp) Role granting ONLY `get,create,update` on `leases` in `coordination.k8s.io`. No wildcards, no cluster scope, no list/watch/delete/patch, no other resources — grep-enforced. A compromised orchestrator token cannot read secrets, mutate workloads, or escalate |
| T-82-10 | Tampering | Lease object | mitigate | Only the bound orchestrator SA holds update on the lease within skp; no other workload SA is granted lease access. RoleBinding subject is scoped to the single orchestrator SA |
| T-82-11 | Spoofing | ServiceAccount identity | mitigate | The Deployment binds an explicit dedicated `orchestrator` SA (was `default`); the token is auto-mounted by the kubelet and not app-supplied, so lease identity cannot be forged from inside the container |
| T-82-12 | Denial of Service | 3-replica lease contention | accept | Bounded by the fixed election timings (Plan 01); k8s Lease optimistic-concurrency handles contention. Live behavior is Phase-83 scope |
</threat_model>
