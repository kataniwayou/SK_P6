<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Quartz scheduler → entry-step sends | The fire gate is the sole authority deciding whether THIS replica may emit entry-step dispatches |
| LeaderState (read) → WorkflowFireJob / enricher | Readers consume the volatile snapshot; they never mutate it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-05 | Elevation of Privilege | WorkflowFireJob fire gate | mitigate | A follower can emit sends ONLY if `IsLeader && IsReady`; the snapshot is read-only to the job and written solely by the election callbacks (Plan 01). A cold (un-hydrated) leader is fenced by the `&& hydrated` term (D-05), preventing lost/duplicate fires on an empty L1 |
| T-82-06 | Spoofing | per-pod bus identity | mitigate | Identity comes from the k8s downward-API `POD_NAME` (kubelet-supplied, not app-controlled); the MachineName fallback is off-cluster only. Distinct identities prevent a queue-name collision that would silently degrade fanout to competing-consumers |
| T-82-07 | Information Disclosure | attributes.role on every log | accept | Role is a coarse leader/follower label, no secret content; it is deliberately on every record for the Phase-83 failover audit |
| T-82-08 | Tampering | in-cluster election gating | mitigate | The election service is registered ONLY when `KUBERNETES_SERVICE_HOST` is present, so a local/test process cannot accidentally start a real elector or contend for the production Lease (D-02/D-06) |
</threat_model>
