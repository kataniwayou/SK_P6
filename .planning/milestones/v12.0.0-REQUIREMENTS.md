## v12.0.0 Requirements — HLTH (Health/Liveness Refactor) — Phase 86 (SHIPPED)

- [x] **HLTH-01**: `/health/live` returns healthy iff the service's watchdog loop has beaten within `k × interval` (default k=3); a genuinely stalled/dead loop goes stale → restart. An infra outage does NOT trip `/health/live`.
- [x] **HLTH-02**: A Postgres/Redis/RabbitMQ outage never crashes the process nor restarts the pod — the fault is caught + logged on every loop, including `ProcessorStartupOrchestrator`'s identity/schema loop; a live broker outage leaves all four services at `RESTARTS 0`.
- [x] **HLTH-03**: One shared `BaseConsole.Core` primitive (`ILivenessHeartbeat` + `LoopLivenessHealthCheck`), opt-in per service; keeper + processor beat at the top of their loop before any infra I/O (keeper's `BitHealthLoop` edge bus-ops no longer block the beat); orchestrator stays `self`-only.
- [x] **HLTH-04**: `/health/ready` = each service's required infra deps plus, for the processor, identity+schema resolved; NotReady never restarts; Redis included for all services.
- [x] **HLTH-05**: No self-heal — once a required dep fails for its readiness `failureThreshold` window, `/health/ready` latches Unhealthy until process restart; migration stays one-shot.
- [x] **HLTH-06**: `KeeperLivenessWatchdogHealthCheck` + `BaseProcessor LivenessWatchdogHealthCheck` are retired; the processor beats unconditionally (the "only when Healthy" gate stays only on the L2 write).
- [x] **HLTH-07**: Startup-gate marking is per service (orchestrator=hydration complete, keeper/processor=first watchdog beat, baseapi=migrations) and a `startupProbe → /health/startup` is added to all four k8s deployments (30/31/32/33-*.yaml).
- [x] **HLTH-08**: The baseapi bus stays capped at `Degraded` (publish-relationship, soft) and is NOT latched.
